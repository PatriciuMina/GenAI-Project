     Defaults I chose (no question needed):
     - Pacing: 3 s after each issue creation, 1 s after other write calls. Both
       can be overridden with SLEEP_CREATE/SLEEP_WRITE.
     - On a "secondary rate limit"/abuse error the script retries once after 60
       s. Any other error stops it with a clear message.

     Script design

     Safety:
     - Constants REPO=PatriciuMina/GenAI-Project and OWNER=PatriciuMina.
     - Every gh call passes --repo/--owner, or repos/$REPO for gh api.
     - set -euo pipefail. Checks up front: gh, jq and python3 are installed and
       gh auth status succeeds.

     Modes:
     - --dry-run (default) runs read-only gh calls and prints WOULD CREATE … /
       SKIP (exists) ….
     - --run makes the changes.
     - -h prints help.
     - Any other argument is an error.
     - All write calls go through one write_call helper. In dry-run it only
       prints; in --run it runs the call, sleeps, and handles retry and errors.

     Parsing: an embedded python3 -I step turns the markdown into JSON, which
     the rest of the script reads with jq.
     - A ticket block starts at ^## T-(\d\d): (.*) and ends at the next ^#  or
       ^##  line. A trailing --- is stripped.
     - Fields extracted per ticket: id, title, points, labels, deps, body.
     - Validation: exactly 99 sequential IDs, each ticket has
       Points/Labels/Depends, every dependency exists. Otherwise the script
       aborts.
     - Body = header line + block text (the Points/Labels/Depends lines are
       kept), with relative links rewritten via posixpath.normpath from
       docs/planning/. http(s) and #anchor links stay as they are.

     Steps (each one idempotent):
     1. Labels
        - Required set:
          type:feature/test/design/diagram/research/docs/report/qa/bug,
          area:backend/frontend/docs, workflow:W1–W5, points:1–5,
          good-first-ticket, no-genai, blocked, plus every other label found in
          the file.
        - Each has a fixed color and a short description from a table in the
          script. A label found only in the file gets a neutral color.
        - Read the existing names with gh label list --limit 200. Create the
          missing ones with gh label create; existing labels are never modified.
     2. Milestone "Mid-term": gh api repos/$REPO/milestones?state=all. If
        missing, create it with POST.
     3. Project (via gh project list --owner):
        - If "UBB Events Board" exists, use it. Else, if "GenAI Pro" exists,
          rename it with gh project edit --title. Else create it.
        - Link it to the repo with gh project link, only if a GraphQL check
          shows it isn't linked yet.
        - Add the "Points" NUMBER field with field-create if it's missing.
        - If the Status field lacks "Todo", replace its options with GraphQL
          updateProjectV2Field, then re-read the option IDs.
     4. Issues T-01..T-99 in order:
        - Read existing issues once: gh issue list --state all --limit 500 
          --json number,title,body,id. Map them by the regex ^\[T-(\d\d)\].
        - Missing ticket: gh issue create with title, body, --label (file labels
          + points:n) and --milestone "Mid-term". No assignees. Then sleep
          SLEEP_CREATE.
        - Every ticket, created or existing: make sure it is on the board with
          gh project item-add, which is idempotent and returns the item ID.
        - Set Points if it is empty. Set Status=Todo only if Status is empty, so
          a re-run never moves tickets the team has already started.
        - The current field values are read once from gh project item-list 
          --format json.
     5. Dependency links (after all issues exist):
        - Rewrite the Depends-on line to T-03 (#3), …. Run gh issue edit 
          --body-file only when the body differs, so a re-run makes no changes.
        - Native relations: GET repos/$REPO/issues/{n}/dependencies/blocked_by,
          then POST with {"issue_id": <database id of blocker>} for each one
          that is missing.
        - If the first POST returns 404/410, print a warning once and skip the
          native relations.
     6. Summary: created / skipped / updated counts for labels, milestone,
        project, issues, board items, body updates and native relations, plus
        the project URL.

     Dry-run caveat: when the project doesn't exist yet, or when issues would be
     created, dry-run prints the dependency rewrites with placeholder numbers
     (#?).
