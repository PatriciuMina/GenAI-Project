     Plan: Spring Boot backend skeleton in /backend

     Context

     Repo has only foundations (CLAUDE.md, ADRs, docker-compose Postgres 16,
     .env.example, usage log). We need a runnable, empty-but-wired Spring Boot
     backend: feature packages, profiles, error handling, temporary security,
     health endpoint, Swagger, and a Testcontainers smoke test. No
     entities/business features.

     Environment checked: Temurin 21.0.13, Docker 29.9 running, no global mvn
     (wrapper must bootstrap itself), root .env exists with
     POSTGRES_DB/USER/PASSWORD/PORT.

     Version decision (for your approval)

     - Spring Boot 3.5.16 — newest 3.x on Maven Central (released 2026-06-25);
       3.5 is the final 3.x line.
       - Caveat to be aware of: 3.5's free OSS support ended 2026-06-30, so no
         further free patches. The only "strong reason" alternative would be
         Boot 4.x (4.1.x stable), but that means Spring Framework 7 / Jakarta EE
         11 / Jackson 3 / springdoc 3.x and contradicts CLAUDE.md + ADRs
         ("Spring Boot 3.x"). For a semester course project, 3.5.16 is the
         pragmatic choice; I recommend it.
     - springdoc-openapi-starter-webmvc-ui 2.10.0 — latest 2.x, built against
       Boot 3.5.16.
     - Maven 3.9.16 via Maven Wrapper 3.3.4 ("only-script" type, downloaded from
       Maven Central — no jar committed).
     - Testcontainers / JUnit 5 / Mockito versions managed by the Boot BOM
       (spring-boot-testcontainers + org.testcontainers:postgresql +
       junit-jupiter).

     Files to create (backend/)

     - pom.xml — parent spring-boot-starter-parent:3.5.16, java.version=21,
       groupId ro.ubb, artifactId events-backend. Deps: starter-web,
       -validation, -data-jpa, -security, postgresql (runtime), flyway-core +
       flyway-database-postgresql, springdoc. Test: starter-test (JUnit 5 +
       Mockito), spring-security-test, spring-boot-testcontainers,
       testcontainers postgresql + junit-jupiter.
     - mvnw, mvnw.cmd, .mvn/wrapper/maven-wrapper.properties (from
       maven-wrapper-distribution-3.3.4-only-script.zip on Maven Central).
     - src/main/java/ro/ubb/events/EventsApplication.java.
     - package-info.java in each of auth, user, organization, event, 
       registration, organizing, common, config (one-paragraph purpose +
       workflow ID; no sub-packages created yet beyond what's needed).
     - common
       - common/dto/ApiError.java record (Instant timestamp, int status, String 
         code, String message, List<FieldErrorDto> fieldErrors);
         FieldErrorDto(String field, String message).
       - common/exception/ApiException.java (base: HttpStatus + code) for future
         feature exceptions.
       - common/exception/GlobalExceptionHandler.java @RestControllerAdvice:
         MethodArgumentNotValidException → 400 VALIDATION_FAILED with
         fieldErrors; ConstraintViolationException,
         HttpMessageNotReadableException, MethodArgumentTypeMismatchException →
         400; NoResourceFoundException → 404;
         HttpRequestMethodNotSupportedException → 405; ApiException → its
         status; fallback Exception → 500 INTERNAL_ERROR (logged, generic
         message).
       - common/controller/HealthController.java GET /api/v1/health → { 
         "status": "UP", "timestamp": ... } (DTO record), annotated for OpenAPI.
     - config
       - config/SecurityConfig.java — stateless, CSRF off, no
         httpBasic/formLogin; permitAll for /api/v1/health, /swagger-ui.html,
         /swagger-ui/**, /v3/api-docs/**, /error; anyRequest().denyAll(). Entry
         point / access-denied handler write the same ApiError JSON (401
         UNAUTHORIZED / 403 FORBIDDEN). Marked TEMPORARY until JWT (ADR-003).
       - config/OpenApiConfig.java — API title/version.
     - resources
       - application.yml (shared): app name; spring.config.import: 
         optional:file:../.env[.properties],optional:file:./.env[.properties]
         (Spring Boot natively reads .env as properties → no manual exports;
         real OS env vars still win); jpa.hibernate.ddl-auto: validate,
         open-in-view: false; flyway enabled, locations: classpath:db/migration;
         springdoc.swagger-ui.path: /swagger-ui.html; exclude
         UserDetailsServiceAutoConfiguration (no generated-password noise).
       - application-dev.yml: url: 
         jdbc:postgresql://localhost:${POSTGRES_PORT:5432}/${POSTGRES_DB},
         username: ${POSTGRES_USER}, password: ${POSTGRES_PASSWORD} — no
         defaults for secrets.
       - application-test.yml: no datasource (supplied by Testcontainers
         @ServiceConnection), quieter logging.
       - db/migration/.gitkeep (no migrations yet; Flyway runs with zero
         scripts).
     - test
       - src/test/java/ro/ubb/events/ApplicationSmokeTest.java — @SpringBootTest
         @AutoConfigureMockMvc @ActiveProfiles("test") @Testcontainers,
         @Container @ServiceConnection static 
         PostgreSQLContainer<?>("postgres:16-alpine"). Asserts: context starts
         (Flyway + JPA validate against real Postgres), GET /api/v1/health → 200
         UP, GET /v3/api-docs → 200, GET /api/v1/anything → 403 with ApiError
         shape.
