⏺ I've added your five answers to the plan. Nothing is built yet: I'm waiting
  for you to approve the plan.

  Your decisions:
  - Token lifetime: 2 hours, with no refresh tokens.
  - JWT handling: Spring's built-in resource-server support with an HMAC secret.
    I don't see a reason to add a separate library.
  - Registration: anyone can register with any email and always gets STUDENT.
  - Passwords: at least 8 characters. I also cap them at 72, because BCrypt
    ignores anything past 72 bytes.
  - Organizations: login is required to see them.
  - Failed login: the same "Invalid credentials" message for a wrong email or a
    wrong password.

  My recommendations you haven't answered yet (they stand unless you change them
  now):
  - Token contents (D6): the token carries the user id, email and role. A role
    change takes effect at the next login.
  - Logged-in user (D7): code gets it as a small AuthenticatedUser object with
    the user's id, email and role.
  - Role levels (D8): PRESIDENT includes ORGANIZER, which includes MEMBER.
  - ADMIN (D9): the permission checks don't let an ADMIN through automatically;
    an endpoint that should allow admins says so explicitly.
  - Register response (D10): returns 201 with the user's profile but no token,
    so the client logs in next. A duplicate email gives 409.
  - Missing secret (D13): the app refuses to start if JWT_SECRET is missing or
    shorter than 32 bytes.
  - Organizations list (D14): a plain list sorted by name, with no paging yet.
  - Mapper (D15): written by hand, no mapping library.
  - 401 vs 403 (D16): no token or a bad token gives 401; a valid token without
    permission gives 403. Both use the existing error JSON.

  Two things you should know before approving:
  - Permission errors would come back as 500. If the existing error handler
    isn't changed, a failed @PreAuthorize check falls through to its catch-all.
    The plan adds handling so it returns a proper 403.
  - Your local .env needs a real JWT_SECRET. It must be at least 32 bytes
    (openssl rand -base64 48 makes one), or the dev app won't start. I won't
    edit .env; I'll only add a placeholder to .env.example.

  The existing smoke test currently expects 403 for protected paths, so I'll
  change it to expect 401.
